# Centralized Theme Management System

This dotfiles repository includes a centralized theme management system that allows you to switch color schemes across all your tools with a single command.

## Supported Tools

The theme system controls colors for:
- **ZSH** - Shell syntax highlighting
- **Starship** - Prompt theme
- **Tmux** - Status bar colors
- **Neovim** - Editor colorscheme
- **WezTerm** - Terminal emulator theme

## Supported Themes

- `tokyonight-storm` (default)
- `catppuccin-mocha`
- `catppuccin-macchiato`
- `nord`
- `onedark`

## Quick Start

### Switch themes

```bash
# Switch to a different theme
theme catppuccin-mocha

# The script will automatically:
# 1. Update the central theme configuration
# 2. Reload your shell colors
# 3. Reload tmux configuration
# 4. Show instructions for restarting WezTerm and Neovim
```

### Check current theme

```bash
theme
```

### List available themes

```bash
theme --list
```

## How It Works

### 1. Central Configuration

All theme definitions are stored in `~/.config/dotfiles/theme.sh`. This file:
- Defines the active theme via `$COLORSCHEME`
- Maps color values for each theme
- Exports application-specific theme names

### 2. Application Integration

Each application reads from the central theme configuration:

- **ZSH** (`.zshrc`): Sources `theme.sh` and uses color variables
- **Starship** (`.config/starship.toml`): Uses palette names
- **Tmux** (`.tmux.conf`): Theme section auto-generated by script
- **Neovim** (`nvim/lua/mike-custom/config/ui.lua`): Reads `$NVIM_THEME` environment variable
- **WezTerm** (`.wezterm.lua`): Reads `$WEZTERM_THEME` environment variable

### 3. Theme Switcher Script

The `theme` command (located in `~/bin/theme`):
- Updates the central `theme.sh` file
- Regenerates application-specific configs
- Automatically reloads shell and tmux
- Provides instructions for manual restarts

## Special Cases

### IntelliJ Terminal

Neovim will always use the `onedark` theme when launched from the IntelliJ terminal (detected via `$INTELLIJ` environment variable), regardless of your global theme setting. This keeps the editor consistent with IntelliJ's theme.

### Manual Restarts Required

After switching themes, you'll need to manually restart:
- **WezTerm**: Restart the app or reload config with `Cmd+Shift+R` (macOS)
- **Neovim**: Exit and relaunch any open instances

Zsh and Tmux reload automatically!

## File Structure

```
dotfiles/
├── bin/
│   └── theme                      # Theme switcher script
├── config/.config/
│   ├── dotfiles/
│   │   └── theme.sh               # Central theme configuration
│   ├── starship.toml              # Starship config (palette auto-updated)
│   └── nvim/lua/mike-custom/
│       └── config/ui.lua          # Neovim colorscheme config
├── zsh/.zshrc                     # ZSH config (sources theme.sh)
├── tmux/.tmux.conf                # Tmux config (theme section auto-updated)
└── wezterm/.wezterm.lua           # WezTerm config (reads $WEZTERM_THEME)
```

## Adding New Themes

To add a new theme:

1. Add theme colors to `~/.config/dotfiles/theme.sh`
2. Add palette to `~/.config/starship.toml` (if not already present)
3. Update `SUPPORTED_THEMES` array in `~/bin/theme`
4. Ensure the theme is available in Neovim and WezTerm

## Troubleshooting

### Theme not applying

```bash
# Reload shell configuration
source ~/.zshrc

# Reload tmux configuration
tmux source-file ~/.tmux.conf

# Check current theme
theme
```

### Colors look wrong

Make sure you've restarted WezTerm and Neovim after switching themes. The theme switcher can only auto-reload shell and tmux.

### Environment variables not set

The theme system relies on environment variables. Make sure:
1. `~/.config/dotfiles/theme.sh` is being sourced in your `.zshrc`
2. You've opened a new shell after switching themes
3. The `theme` script is in your `$PATH` (should be in `~/bin`)
